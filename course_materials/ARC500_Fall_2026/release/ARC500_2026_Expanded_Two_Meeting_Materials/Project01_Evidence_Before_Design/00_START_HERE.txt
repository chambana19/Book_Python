PURPOSE
Use a small architectural dataset to make one bounded, reproducible claim.
The project is about the quality of the evidence chain, not the number of
plots or lines of code.

START IN THIS ORDER
1. Read 01_PROJECT_BRIEF.txt.
2. Copy THIS WHOLE PROJECT FOLDER to a working location; do not edit the
   originals. Keep the folder structure as shipped -- analysis.py and
   evidence.py find your data at ../Data/ and write their exports to
   ../Submission/, both relative to the Starter_Code folder they sit in. If you
   copy the two .py files out on their own into a flat folder, they will stop
   with FileNotFoundError on Data/building_rooms.csv, because there is no
   longer a Data folder one level up from them.
   analysis.py and evidence.py are already named exactly as the deliverables
   require, so copying them needs no renaming.
3. Choose the course dataset or obtain written approval for another dataset.
4. Complete the weekly milestones in 02_MILESTONES_AND_CHECKLIST.txt.
5. Use 03_RUBRIC.txt while revising—not only before submission.
6. Complete the README, data dictionary, and AI-use record.
7. Build the six-slide pin-up (cover plus five content slides) with the supplied
   PowerPoint template.
8. From this project folder, run `python validate_submission.py .`. Resolve every
   FAIL line before uploading; WARN lines require a documented manual check.

CORE OUTPUTS
- One or two Python .py files
- One cleaned CSV and one grouped-summary CSV
- Two static PNG figures
- One map PNG OR one animation GIF
- A 600–800-word illustrated evidence memo
- README, data dictionary, AI-use record, and six-slide pin-up

RULE OF COMPLETION
A result is not complete until the code runs from the project folder, the
exports exist, the important numbers have been checked, and the claim names
its limitations. An EXPECTED TODO STOP is the scaffold protecting you from an
unfinished artifact; a CHECK FAILURE means code ran but the evidence is wrong.
